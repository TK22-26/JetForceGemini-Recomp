## Execution order

1. **Make the short comparison trustworthy.** Reuse the existing US input and
   focused captures. Compare initial FlashRAM, Controller Pak/device state,
   delivered input, and state at equivalent guest execution hooks. Investigate
   the first unexplained boundary through poll 577. Separately qualify the
   CPU oracle with the existing microtest; evaluate an isolated corrected
   Mupen core or Ares reference for disputed semantics. A core change needs its
   own boot/save/timing validation. Keep the original TAS core pinned.
   Deliverable: one short reproducible command yielding either an aligned
   semantic difference with operands/call context or a specific failed
   alignment condition. No automatic matching by shifted hashes or ignored
   fields. First investigation budget: two hours, followed by a written
   architecture decision if equivalence remains unproved.

2. **Close an engineering repair loop on that prefix.** Feed a valid defect
   report to a bounded coding worker, build only affected targets, independently
   replay the failing case and previous passing corpus, then accept or reject
   the candidate with evidence. Use the existing authenticated local worker;
   no new paid API dependency. If the next difference is an oracle defect,
   repair/qualify the reference first. A reversible seeded fault can exercise
   the workflow, but must be reported separately from a real game fix.
   Deliverable: failure -> diagnosis -> candidate -> independent retest ->
   durable result, including rejected candidates and restart recovery.

3. **Use demonstrations to construct routes.** Refine the TAS brackets around
   the current Goldwood obstacle into player trajectories, camera orientation,
   interactions, and room transitions. Match JP and US room/actor/geometry
   identities before transferring route knowledge. Author a small semantic
   waypoint/mechanic route where extraction is incomplete. Execute it through
   ordinary US controller input and verify endpoints independently. Do not
   replay JP timing into US or transfer JP savestates. A small map or a
   game-specific behavior is an acceptable engineering result. Full JP native
   support is not a prerequisite and is not added by this plan.

4. **Expand a regression corpus while repairing native.** Every newly qualified
   US route enters the short comparison/repair workflow. Build named scenarios
   for encounters, weapons, dialogue, doors, bosses, save/load and recovery.
   Test functions/subsystems from captured operands when that isolates a defect
   faster; retain end-to-end runs to validate integration. Add perturbations
   around successful routes and use exploration for uncovered branches.
   Whole-game coverage still requires a declared denominator beyond the TAS.

5. **Accelerate and finish acceptance.** Profile measured replay/build costs.
   Implement complete native snapshots when prefix replay dominates iteration
   time; prove their execution/device/scheduler equivalence. Expand determinism
   and regression runs to the full accepted corpus. Complete all scope gates,
   then implement and verify the selected enhancements. Documentation alone
   does not make enhancements trivial or accepted.

Steps 1–2 are the primary critical path. Route extraction in step 3 can run
independently. Do not make native repair wait for a campaign-playing bot.

## Resource and plateau policy

The [investigation-level guard](autonomy-progress-guard.md) now mechanically
limits supervisor-launched work across job IDs and restarts. It has passed a
real-subprocess repetition/recovery/timeout trap. Its main-ledger rollout is
enabled behind the existing pause marker; general evidence-grounded recovery
planning remains open. Supporting artifacts do not automatically earn progress.

- Allocate most engineering time to trustworthy comparisons and verified
  repairs. Limit route acquisition to a separate bounded workstream until the
  repair loop has passed its end-to-end acceptance.
- Two runs with no new completed objective or useful distinguishing evidence,
  or 30 minutes on the same search hypothesis, trigger a strategy review.
  Change the map, mechanic, observation, or experiment; do not merely increase
  the node/depth budget or generate another status artifact.
- A diagnostic must state the competing explanations and which observation
  will distinguish them before launching. Reuse sealed evidence when it
  answers the question. Avoid recapture solely for unrelated source changes.
- Use available parallel workers for independent tasks: reference semantics,
  TAS-to-US route mapping, and native implementation/retest. Keep their code
  ownership and output directories separate. Shared binaries and accepted
  fixtures have one integrator. Parallelizing identical blind searches is not
  the intended use of a swarm.
- No broad search job is currently running after this review. Resume gameplay
  experiments only with the new route hypothesis and a declared success gate.
